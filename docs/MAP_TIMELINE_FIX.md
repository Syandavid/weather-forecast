# v26 云雨时间联动修复

## v27.1：粗糙显示的后续修正

- 原覆盖图仅96×96像素，区域采样间距固定1.75度，颜色和透明度硬分档。现按视口比例、设备像素密度绘制，最长1024像素、总像素不超过40万；区域采样预算为48/81/96点，自适应分配，最小目标间距12公里仅用于限制采样开销，不代表数据源精度。
- 对采样值做保形插值：保留原采样节点，不生成超出范围的新雨量极值，不跨缺失值补晴天。雨量色阶和低雨量透明度连续过渡，云量覆盖透明度减小，减少遮挡地名。
- 后台Worker负责生成覆盖图，支持时使用OffscreenCanvas在后台编码PNG。只保留一个在算任务；期间选中别的时刻，旧结果不会覆盖新视野，只计算最新需要的帧。缓存最多8帧，播放等待当前帧完成，不积压绘制任务。旧浏览器降级为主线程绘制，速度可能较慢。
- 广州本地视野实测绘制801×498像素、11×7个采样点；这改善像素和插值效果，不是把模型升级为街道级预报。[Open-Meteo文档](https://open-meteo.com/en/docs)说明可用模型和原始空间分辨率因地区不同，重复查询更密的位置不能保证获得更多独立数据。
- 29项测试覆盖时间联动、缺失值、范围保持、渐变连续性、渲染预算、区域采样、Worker消息与旧响应丢弃、缓存上限。

## 原因

默认 radar 开启而 precip 关闭；原 `needsMet` 与绘制函数仅在 precip 开启时绘制未来降水。卫星基底/高清叠加只有初始化 URL，没有订阅时间选择。此外，旧预报超出时效会回退当前值，容易产生不随时间变化的错觉。

## 行为

- 历史：雷达切对应可用帧；红外按所选时间取10分钟帧，最新观测预留50分钟延迟；说明栏显示实际请求时次。真实色日合成按日期切换，同日不变，不人为制造移动。
- 未来：雷达开关或降水开关开启即可绘制逐小时降水；新增独立预报云量开关。隐藏旧卫星观测，避免把它当作未来影像。返回历史时恢复观测。
- 云雨使用现有 Open-Meteo 多位置小时数据，按地理采样网格和墨卡托投影插值成半透明覆盖图。白灰表示云量，蓝紫表示小时降水；不等同卫星实拍、雷达回波或新增分辨率。相邻时刻数据相同可以显示相同，不合成虚假移动。
- 缺失字段/超出预报时效不回退当前数据；加载或缺数据会标明。缩放期间旧覆盖图保持原地理范围，待新视野数据替换；城市级视野缓存键跟随缩放精度，避免平移仍复用远处网格。
- 删除把红外亮度当作降水来源的分支，避免重复叠加相同雷达。

## 数据来源限制

- [RainViewer Weather Maps](https://www.rainviewer.com/api/weather-maps-api.html)：历史雷达约两小时、10分钟帧；帧时间不代表每个雷达站的精确观测时间。接口覆盖空白不等于无雨。
- [RainViewer transition](https://www.rainviewer.com/br/api/transition-faq.html)：公开接口未来 nowcast 自2026年起取消，本项目不能把历史帧称为未来雷达。
- [NASA Himawari](https://gibs.earthdata.nasa.gov/wmts/epsg3857/best/Himawari_AHI_Band13_Clean_Infrared/)：红外地球同步卫星观测有区域范围和发布延迟，不保证所有时间/地点可用。
