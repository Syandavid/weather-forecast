# 天气产品评估与 v25 更新

评估基于本仓库 v24 源码、当前公开产品资料和实际网页流程。目标用户是需要同时看城市天气、台风、卫星与出行影响的手机用户。本轮不包含付费数据服务采购或新增服务端。

## 市场特点和产品取舍

| 参考产品 | 可核对的特点 | 本项目当前痛点 | 本轮决策 |
| --- | --- | --- | --- |
| [Windy](https://www.windy.com/menu) / [模型比较](https://community.windy.com/topic/7930/tutorial-how-to-compare-all-forecast-models-for-a-specific-location) | 天气图层、收藏、多个预报模型比较 | 单一结果无法看出分歧；地图默认自动播放让时刻不断变化 | 新增 ECMWF、GFS、ICON 三天最高温/日降水对比；默认停留当前时刻 |
| [Apple Weather](https://support.apple.com/en-us/105038) | 短临降水与官方极端天气信息有地区覆盖限制 | 旧缓存仍显示暂无风险；模型提醒易被当作官方预警 | 数据时刻、时区、过期提示前置；在风险页区分模型与官方信息 |
| [Zoom Earth](https://zoom.earth/) | 卫星、雷达、台风及预报各有来源和更新频率 | 卫星静态观测与未来时间轴被混为一谈 | 明确卫星不随未来预报改变，雷达与预报降水分别标示 |
| 日常出行需求（本次产品判断） | 用户最终要决定何时出门、是否换计划 | 穿衣卡和气象数字不能直接给出出门时段 | 新增散步/跑步/骑行，两小时白天时段筛选和原因解释 |

特色应集中在“天气是否影响我的城市和行程”，同时保持台风地图可查。多模型对比只在展开时请求；出行时段复用既有小时预报，避免首屏继续增加网络负担。

## 本轮交付

- 多模型对比：ECMWF IFS 0.25°、GFS Seamless、ICON Seamless；未来三天最高温、日累计降水，按日期对齐，展示模型温差。模型失败显示暂缺，支持更新；城市切换丢弃旧请求；缓存30分钟。模型差值不是统计概率。
- 出行窗口：未来24小时内不重叠的连续2小时白天时段，按活动区分体感、阵风、UV阈值；排除雷暴、冻雨、雪和较高降水风险。无合适窗口或缺数据时说明原因，不勉强推荐。它是天气条件筛选，不包含实时路况、地形、医疗个体化评价。
- 时间与雨量：按所选城市时区解析时间并处理夏令时；雨量按区间累计计算，部分小时按重叠时间比例估算；显示15分钟/60分钟时段单位；避免六个卡片漏掉中间短时雷暴。官方 [Open-Meteo 文档](https://open-meteo.com/en/docs) 说明部分区域15分钟数据来自小时插值，因此不宣称全球真实分钟级预报。
- 数据可信度：3小时以上的当前天气标记过期；不据旧数据输出短临安心提示；缺字段保留未知，极端风险文案显示实际覆盖截止；区分设备获取时间、城市天气有效时刻和模型起报时次。
- 地图体验：地图组件按需加载；地图默认不自动播放，手动选时即暂停，新增“现在”按钮和键盘选择；同视野请求合并，过时响应丢弃，失败后30秒退避，降水关闭后不残留预报点；修复卫星异步切换覆盖用户最新选择。
- 可读性：恢复网页缩放，长时效预报增加趋势提醒，手机宽度显示模型表格和活动卡。

## 后续重要机会

| 优先级 | 功能 | 依赖与理由 |
| --- | --- | --- |
| P1 | 正式官方预警接入和订阅推送 | 需要覆盖目标地区的授权预警源、后台任务和推送服务。静态页面内提醒不能保证关闭页面后送达 |
| P1 | 地图资源部署和区域网络优化 | 按真实用户地区测量首屏耗时、失败率；必要时采购数据代理/CDN，记录覆盖盲区，不能把空白雷达当作无雨 |
| P1 | 正式标准地图数据 | 当前边界覆盖仍是预览，本轮不变更和不认定其几何正确性；正式地图依赖可靠授权来源 |
| P2 | 路线天气升级 | 现有路线依赖公共服务，进一步需要按每个途经点预计到达时间评估、路线替代方案及服务稳定性 |
| P2 | 模型分歧随时间曲线、用户偏好 | 先验证本轮模型比较使用率，后续增加风速对比、单位、活动阈值自定义 |
| P3 | 闪电、火点、花粉和海况 | 应在有明确场景和数据覆盖时接入，避免层叠开关继续挤占手机地图 |

## 验证方法

`node --test scripts/test_insights.cjs` 覆盖城市时区/夏令时、旧缓存、空值、两小时区间累计、短时雷暴、短临回退、活动限制、地图并发/乱序/失败退避。`python scripts/validate_project.py` 检查项目完整性及原有温度网格隐藏约束。真实浏览器检查模型加载、活动切换、城市切换及地图现在/播放/选时流程。实际手机 Safari 与各地区网络速度仍需设备侧验证；不把源码选项或单个瓦片节点当成地图全覆盖证明。

### 本地实测记录（2026-09-05）

- 13 项行为测试通过，另包含模型按需请求、部分失败/异常字段、缓存、切城乱序响应和雷达元数据加载后的时刻保持；项目完整性与内联 JavaScript 语法检查通过。
- 浏览器在 390 × 844 手机宽度下检查活动卡和模型表格；上海与纽约实际请求均返回 ECMWF、GFS、ICON 三天结果。纽约天气显示 `America/New_York`，地图采用相同当地时间，不再使用设备北京时间。
- 实际操作地图播放、时间轴 End、回到“现在”；选时自动暂停，雷达元数据加载完成后保持当前时刻。测试页未发现 JavaScript error 级日志。
- 这些结果不等于真机 Safari 验证、所有地区瓦片覆盖验证或官方预警资质验证。
